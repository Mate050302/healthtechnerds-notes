## 할 일 1. 꼭지마다 signal 필드를 채운다

지금 노트에는 `insight` 필드만 있다. 여기에 `signal` 필드를 새로 넣는다.

- **insight** = 3개월 안에 앱에서 만들 수 있는 것. 지금 있는 값을 그대로 둔다.
- **signal** = 지금 당장 만들 것은 아니지만 **미국 소비자가 무엇에 돈과 시간을 쓰고 있는지** 보여 주는 흐름.

실행할 것을 찾으려면 먼저 사람들이 어디에 이미 돈을 쓰고 있는지 알아야 한다.
그래서 만들 수 없는 것이라도 수요가 어디 있는지 드러나면 남긴다.

예를 들면 이런 것이 signal 이다.
- 승인 절차 밖의 주사제를 소비자가 스스로 사 오는 흐름
- 무료 AI 상담 창구로 사람이 몰리는 흐름
- 비만 치료제를 시작한 사람이 계속 맞기 어려워하는 흐름
- 온라인으로 처방약을 파는 회사에 사람들이 멤버십 비용까지 내고 사는 흐름

판단 기준은 두 가지이고 **둘 다** 맞아야 한다.
1. 미국 소비자가 직접 돈이나 시간을 쓰는 행동이 드러나는가
2. 그 규모나 방향을 보여 주는 근거가 원문에 있는가

**signal 이 아닌 것**: 병원과 보험사 사이의 돈 이야기, 청구 업무, 기업 인수합병, 정부 규제 그 자체.
이것들은 소비자 행동이 아니다. 보이지 않으면 `null` 로 둔다. 억지로 채우지 않는다.

signal 은 2~4문장으로 적는다. 무엇이 벌어지고 있는지와, 그것이 소비자의 어떤 사정을 말해 주는지를 담는다.

## 할 일 2. issue_insight 를 불렛 두 갈래로 바꾼다

지금은 긴 서술 한 덩어리다. 이것을 아래 형태로 바꾼다.

```json
"issue_insight": {
  "verdict": "yes 또는 no",
  "summary": "이 회차 전체 판단 한두 문장. 길게 쓰지 않는다.",
  "build": [
    { "title": "짧은 제목 한 줄", "detail": "무엇을 만들 수 있는지 한두 문장", "section": 5 }
  ],
  "signal": [
    { "title": "짧은 제목 한 줄", "detail": "소비자가 어디에 돈과 시간을 쓰는지 한두 문장", "section": 9 }
  ]
}
```

- `summary` 는 **한두 문장**이다. 지금 들어 있는 긴 서술에서 회차 전체 판단만 남기고, 나머지는 불렛으로 옮긴다.
- `build` 에는 `insight` 가 달린 꼭지를, `signal` 에는 `signal` 이 달린 꼭지를 넣는다.
- `title` 은 한 줄로 짧게 적는다. 목록에서 훑어보는 자리이기 때문이다.
- `detail` 은 한두 문장이다.
- `section` 은 근거가 된 꼭지 번호다. 첫 꼭지가 1이다.
- 둘 다 비면 `verdict` 를 `"no"` 로 두고 `summary` 에 왜 없는지 적는다.

## 반드시 지킬 것

- 원문에 없는 사실을 지어내지 않는다.
- `insight` 값은 바꾸지 않는다. `signal` 만 새로 넣는다.
- `tldr`, `title_ko`, `hook`, `themes`, `sections` 의 다른 필드(summary·author·experts·cases·notes·skip)는 **손대지 않는다.**
- 이모지와 엠대시를 쓰지 않는다. 문체는 "~다" 체로 통일한다.
- 비유 표현을 쓰지 않는다.
